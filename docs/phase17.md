## 3. コンセプト：Ember Hollow（燠の洞）

- **どんなゲームか:** ターン制の短いローグライク。
  - 燠（おき）を 1 つ持って、洞窟を 5 階まで下りる。
  - 燠は、明かりであり、時間でもある。光の届く範囲がそのまま見える範囲で、毎ターン少しずつ弱まる。各階の篝火（かがりび）でだけ、また強くなる。
  - 洞の生き物は闇に棲み、光に反応する。5 階にいる、洞を暗く保つ生き物を倒せば勝ち。死ぬか、燠が消えれば負け。
- **柱:**
  1. 毎ターンが判断。移動、待機、戦闘、アイテムの使用。次のターンに傷を負わせうる脅威は、すべて先に見えて読める。
  2. 光が資源。遠くまで見えることと、時間が残ることは同じ。燠をどう使うかが、ランの中心の取引。
  3. ランは短く、毎回違う。1 ランは 15〜30 分。階は種（seed）から作られ、種が違えば別のラン、同じ種なら同じラン。
- **制約:**
  - Node.js 20 とブラウザで動く JavaScript。依存なし、ネットワークは使わない。ルールのコードは、2 つの遊び方で共有する。
  - **人のためには、ブラウザのページ。** `repo/index.html` は、サーバーなしでファイルから直接開け、キーボードかマウスで遊べる。階を格子で描く。
  - **チームのためには、入力のスクリプト。** `run_play`（`node play.js {script}`）、`run_trace`、`run_tests`（`node --test`）。スクリプトの書式（種の選び方を含む）はビルドが決め、`repo/manual.md` に書く。
  - 決定的。同じ種と同じ操作なら、いつも同じラン。
- 敵の種類、アイテム、階の大きさ、数値は、すべて Studio が決める。

## 4. 外部の判定（実行前に決める。packet には入れない）

Close の後に、私が判定する。スクリプトでの判定は、`repo/manual.md` と、`project.md` に宣言されたコマンドだけを使う。

| 基準 | 内容 |
|---|---|
| V1 スクリプトで遊べる | 説明書の書式で書いたスクリプトで、ある種のランを `run_play` で進められる |
| V2 作りが制約どおり | `node --test` が通る。依存がない（`package.json` の依存も、組み込み以外の `require`/`import` もない）。ネットワークを使うコードがない |
| V3 中身がある | 5 階まで進め、5 階にボスがいる。敵は 3 種類以上、アイテムは 3 種類以上。遊んで（`run_trace` も使ってよい）確かめる |
| V4 決定的 | 同じ種と同じスクリプトなら、出力が完全に同じになる。違う種なら、最初の階が違う |
| V5 勝ちも負けもある | 勝ちに至る操作の列が 1 つ以上ある（Studio の QA や Playtester が残したものでもよい）。負けて終わる列もある |
| V6 ブラウザで遊べる | `index.html` をファイルから直接開くと、コンソールのエラーなしに階が描かれ、キーかクリックの操作で 1 ターン進む。Chrome の開発者ツールで確かめる |

- 「楽しいか」は、Owner がブラウザ版を遊んで判断する。私が中身をすべて読んでから、claude.ai のページとして渡す。
