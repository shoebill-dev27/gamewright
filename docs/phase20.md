# Phase 20 設計：はっきり大きなゲームを、コンセプトから作らせる

状態: **設計**（2026-10-27。Owner の依頼「実証が小さすぎるので、さらにもっとボリュームのあるゲーム一本挑戦してみてほしい」により進める）

## 1. 課題

- これまでコンセプトから作らせたゲームは、2 本とも小さかった。
  - Lamplight Keeper: ルール 1 つ、夜 3 つ。
  - Ember Hollow: 5 階、敵 3 種とボス、アイテム 2 種。JavaScript で約 1,100 行。
- 提案資料でも「実証は小さなゲームだけ」を限界に挙げた。
- 仕組みの数も中身の量もはっきり大きいゲームを、Studio がどこまで作り切れるかは、まだ分からない。

## 2. 方針

- コードは変えない（問題が見つかれば直す）。
- 新しいコンセプト `examples/fixtures/kitsunebi-pass` を渡す。
- Owner の依頼（日本語）: **「このコンセプトで、宿場町から峠の社まで通して遊べる版を作ってほしい。絵つきでブラウザで遊べるように」**
- executor: Claude（Sonnet）。予算は executor 200 回まで。大きな Goal なので、これまでより多く見込む。
- Owner 確認には、これまでどおり私が答える。範囲の判断は Studio の推奨を採る。費用の判断は自分で決める。
- **バーチャルオフィス（Phase 19）で、ライブに観察する。**

## 3. コンセプト：Kitsunebi Pass（狐火の峠）

- **どんなゲームか:** 江戸の山道を舞台にした、ターン制の「不思議のダンジョン」型ローグライク。
  - 旅人が、峠のふもとの宿場町から出発し、山道と霧の社の 10 階を登って、頂上の狐の社を目指す。
  - 1 歩が 1 ターンで、旅人が動くと、階の生き物もみな動く。
  - 満腹度、限りのある荷物、使ってみるまで正体の分からない道具が、小さな判断の連続を生む。
  - 失敗しても無駄にはならない。町の倉庫に預けた物は、次の挑戦でも残っている。
- **柱:**
  1. 一歩ごとに判断。移動、攻撃、食事、道具の使用は、どれも 1 ターン。次のターンに動ける脅威は、見えて読める。
  2. 道具で切り抜ける。草、巻物、杖、お札が、それぞれ別のやり方で窮地を変える。力押しより、使いどころ。
  3. 登って、負けて、強くなって戻る。1 回の挑戦は 30〜60 分。宿場町（店、倉庫、宿）が、挑戦をまたいで進歩を持ち越す。
- **制約:**
  - Node.js 20 とブラウザの JavaScript。依存なし、ネットワークなし。ルールは 2 つの遊び方で共有する。
  - 人のためには、絵つきのブラウザのページ。階、旅人、すべての生き物と道具を、文字ではなく絵で描く（コードで描いてよい）。画面の文言は日本語。
  - チームのためには、入力のスクリプト（`run_play`、`run_trace`、`run_tests`）。
  - 決定的。同じ種と操作なら同じ挑戦。
  - プレイヤーが入力したデータ（種、名前）を、HTML としてページに入れない（Phase 17・18 の XSS の教訓を、Owner の制約として最初から書いた）。
- `page: index.html` を最初から宣言する。Studio は、最初から画面を撮って確かめられる。
- 敵、道具、数値、階の作り、町の仕組みの細部は、すべて Studio が決める。

## 4. 外部の判定（実行前に決める。packet には入れない）

Close の後に、私が判定する。スクリプトでの判定は、`repo/manual.md` と、`project.md` に宣言されたコマンドだけを使う。

| 基準 | 内容 |
|---|---|
| K1 量 | 10 階まで登れる。区間が 2 つ以上あり、階の主（ボス）が 2 体以上。生き物は 8 種以上、道具は 12 種以上（4 系統以上） |
| K2 仕組み | 宿場町に、店（買う・売る）と倉庫がある。倉庫に預けた物が、次の挑戦で取り出せる。満腹度があり、食べ物で戻る |
| K3 遊び切れる | 町を出て頂上に着く（勝つ）操作の列が 1 つ以上ある。Studio が残したもの（ボットや QA の手順）でもよい。負けて終わる列もある |
| K4 決定的 | 同じ種と同じスクリプトなら、出力が完全に同じ。違う種なら、最初の階が違う |
| K5 ブラウザ | `index.html` をファイルから直接開くと、コンソールのエラーなしに描かれ、キー操作で進む。旅人、生き物、道具が絵で描かれている（画面を撮って確かめる） |
| K6 作りが制約どおり | `node --test` が通る。依存なし、ネットワークなし。入力したデータを `innerHTML` などで HTML としてページに入れていない |

- 量（コードの行数、試験の数、かかった時間と費用、Owner 確認の数）は、判定ではなく記述として記録する。
- 「楽しいか」は、Owner がブラウザ版を遊んで判断する。私が中身を読んでから、claude.ai のページとして渡す。
