# G-001: ダッシュ中の被ダメージ不具合を修正する

## Owner request

> ダッシュ中なのにダメージを受けることがある。再現できるので直してほしい。

## Interpretation

報告された被ダメージを再現し、仕様に反する挙動を修正して、ダッシュ時のダメージ判定が既存の仕様どおりに動くことを独立した検証で確認する。

戦闘の方向性変更、新しい入力の追加、無関係なバランス調整は対象外。Studio は仕様、技術方式、再現結果、検証判定を決定しない。

## Unknowns

- Observe: QA は模擬資料の記述と仕様との不一致を報告したが、再現条件・時系列・試行結果は未確定。補足観察資料を得て QA の追加観察が必要。
- Diagnose: 原因は未確定。局所的な原因調査は Build の責任範囲とし、独立した技術調査が必要と判明した場合に Technical Director を追加する。
- Decide: 方向・優先順位・範囲の選択は発生していないため省略。
- Design: QA によれば、ダッシュ全期間の無敵という期待挙動と受け入れ条件は既存仕様から確定できるため省略。入力不能中のダッシュ予約や終了と命中が完全に同時の場合を、新たに定義する作業は含めない。
- Plan: 技術的な難度・影響範囲は未確認。非自明・高リスク・複数システムへの影響が判明した場合に追加する。
- Build: 修正を予定するが、再現報告の補完後に開始する。
- Verify: Build 後は必須。仕様と受け入れ条件に対し、キーボード／ゲームパッド、30／60 FPS の組み合わせを独立検証する。
- Play: 体験や感触の改善依頼ではないため省略。
- Review: 体験 Goal や方向 Decision を伴わないため省略。
- Next: 検証後に Studio が Owner 向けに結果と残件をまとめる。

## Route changes

2026-10-10 — 最初の Observe を完了として記録。結果は [02-qa-to-studio.md](02-qa-to-studio.md)（`outcome: question`）。工程の完了は、再現報告の完成や修正の完了を意味しない。

この packet には補足観察資料がなく、参照先である戦闘仕様・模擬ビルドの本文も含まれない。QA の完全な Role 契約、reproduce-defect Skill、前回の入力 Handoff 本文もない。Studio は不足資料や未観察の結果を作成して補うことはできず、次の受領者の Load を確認する Route 手順を完了できない。

方向変更、範囲拡大、不可逆な操作、Goal の再解釈などの Owner 判断事項は現在発生していない。情報不足を Owner の選択問題には置き換えず、Goal は active のまま資料待ちとする。02 の内容と宛先は変更しない。新しい Handoff は未作成。
