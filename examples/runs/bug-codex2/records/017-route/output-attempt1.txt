# 16: studio → qa — ダッシュ時の被害判定を独立検証する

## Task

仕様、既存の AC-1〜AC-6、対象ビルドと模擬観察資料から独立 Verify を行い、結果を Studio に返す。最初に資料の存在とビルド対応を確認し、不足を期待結果で補わない。

## Context

Owner の依頼は「ダッシュ中なのにダメージを受けることがある。再現できるので直してほしい。」である。既存仕様への修正を扱い、戦闘の方向変更やバランス調整は対象外。

本プロジェクトは dry-run で、実行とは模擬ビルドと試行資料を読むことを意味する。実機計測や実コードのテストとして報告しない。

## Findings

### 入力準備状況

対象識別子は `0.3-G001-15`。次の二資料は生成予定先であり、Studio は本 Route で存在・内容・対応を確認していない。

- `sim/build-0.3-G001-15.md`: 読み方と観察可能な挙動を記した模擬ビルド。
- `sim/qa-G001-15.md`: 設定、実際に生成された模擬イベントとハート変化、無効試行、未確認項目を分けた観察資料。

runtime が両資料を用意してから検証を開始する。旧ビルドや識別子の異なる資料を、対応の根拠なしに修正後の証拠へ置き換えない。実装の説明や「直った」という宣言は検証証拠にしない。

### 検証範囲

正式な受け入れ条件は `11-qa-to-studio.md` と `design/combat.md` を参照する。以下は引き継がれた試行要件の要約であり、原文を変更しない。矛盾や未定義の期待挙動は Studio に返す。

全項目を PC の30 FPS・キーボード、30 FPS・ゲームパッド、60 FPS・キーボード、60 FPS・ゲームパッドで確認する。

| 条件 | 確認対象 |
|---|---|
| AC-1 | 先行被弾なしのダッシュ前半・後半で、成立した接触／弾命中によるハート減少がない |
| AC-2 | 通常被弾後、0.3秒の入力不能終了を観察してから開始したダッシュ中に追加被害がない |
| AC-3 | 先行被弾から0.8秒が経過した後も、継続中のダッシュで追加被害がない |
| AC-4 | ダッシュ終了後も、先行被弾から0.8秒まで追加被害がない |
| AC-5 | 保護のない通常被弾で1ハート減少、0.3秒入力不能と回復、0.8秒の被弾後保護が維持される |
| AC-6 | ダッシュ4タイル・0.25秒、既存起点から0.6秒のクールダウン、ダッシュ中の攻撃予約と終了時の一度の発動が維持される |

AC-1〜AC-4 は Grub 接触と Spitter 弾命中を独立に確認する。AC-1 の前半・後半も別試行とする。

追加回帰は全4環境・両命中源で確認する。

- 被弾後の保護がダッシュより先に終了する場合と、ダッシュが先に終了する場合の双方で、両方の保護終了後に通常被害が成立する。
- 保護中の異なるフレームで少なくとも2回の成立した命中を受けても、保護が延長されない。
- 先行被弾なしのダッシュ中に複数命中を防いだ後、ダッシュ終了後に通常被害が成立する。
- 防いだ命中により新しい入力不能が発生しない。

### 観察資料の必要条件

各試行には、ビルド識別子、環境、初期ハート、配置、敵と弾の条件、入力・命中・ハート変化・ダッシュ開始終了の実際の時刻が必要。予定時刻と実際の模擬イベントは分離する。

接触／弾命中の成立が記録されていない通過を保護成功に数えない。AC-3 は「被弾後0.8秒の終了 < 命中 < ダッシュ終了」、AC-4 は「ダッシュ終了 < 命中 < 被弾後0.8秒の終了」の実際の前後関係を確認する。

フレーム番号、delta time、同一フレーム内のイベント順序、論理時間と観察フレームを照合する。30 FPS の0.25秒について独自の許容誤差を設けない。同時境界、命中不成立、予定外の先行被弾、必要な前後関係を満たさない試行は該当条件の証拠に数えない。

AC-6 は既存クールダウン起点の根拠を必要とする。起点をダッシュ開始または終了と仮定しない。起点を確認できない場合は当該項目を未確認とする。

有効・無効・未実施を分離し、条件別の試行数と被害発生数を記録する。生成不能な配置や観察があれば、その不足を具体的に示す。
