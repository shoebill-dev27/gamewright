# 16: studio → qa — 模擬ビルドのダッシュ被害判定を独立検証する

## Task

ビルド `0.3-G001-15` を仕様と既存の AC-1〜AC-6 に照らして独立検証し、追加回帰も確認する。条件別の証拠と判定、未確認事項を分け、結果を Studio に返す。

## Context

Owner の依頼は「ダッシュ中なのにダメージを受けることがある。再現できるので直してほしい。」である。既存仕様への修正が対象であり、戦闘の方向性やバランス変更は対象外。

このプロジェクトは dry-run であり、実行とは模擬ビルドと生成された試行資料を読むことを指す。実機や実コードの実行コマンドはない。模擬資料による判定を実機検証として報告しない。

## Findings

### 対象資料と開始条件

- 対象ビルド: `sim/build-0.3-G001-15.md`
- 試行・観察資料: `sim/qa-G001-15.md`
- 仕様: `design/combat.md`
- 既存の受け入れ条件: `goals/G-001-dash-damage/11-qa-to-studio.md`

対象の生成資料は本 Route packet に含まれておらず、生成済みとは確認していない。まず資料の有無とビルド識別子の対応を確認する。資料がない、識別子が違う、期待結果しかなく観察がない場合は該当範囲を検証不能として返す。旧ビルドや試行予定を修正後の証拠にしない。

以下は試行条件と期待挙動の整理であり、観察結果や合格の主張ではない。原典の AC と設計を確認し、不一致があれば推測で補わず報告する。

### 検証範囲

PC の次の全4環境を区別する。

- 30 FPS・キーボード
- 30 FPS・ゲームパッド
- 60 FPS・キーボード
- 60 FPS・ゲームパッド

AC-1〜AC-4 は Grub 接触と Spitter 弾命中を別試行で扱う。AC-1 は前半・後半も分ける。

`t` は先行被弾からの経過時間、`d` は実際のダッシュ開始時刻。指定時刻は試行目標であり、実際のイベント順序を証拠で確認する。

| 条件 | 試し方 | 期待挙動 |
|---|---|---|
| AC-1 前半 | 先行被弾なしでダッシュし、`d+0.07秒`付近に命中 | ダッシュ中にハートが減らない |
| AC-1 後半 | 別試行で`d+0.18秒`付近に命中 | ダッシュ中にハートが減らない |
| AC-2 | t=0で通常被弾。0.3秒の入力不能終了を観察した最初の入力可能な機会にダッシュし、`d+0.10秒`付近に命中 | 初回以外にハートが減らない。入力不能中の予約で代用しない |
| AC-3 | t=0で被弾、t=0.70付近にダッシュ開始、t=0.85付近に命中 | 被弾後0.8秒を過ぎてもダッシュ中はハートが減らない |
| AC-4 | t=0で被弾、入力可能になった後のt=0.34付近にダッシュ開始、t=0.70付近に命中 | ダッシュ終了後も先行被弾から0.8秒までハートが減らない |
| AC-5 | 保護なしで Grub 接触。t=0.15、0.45、0.70付近にも接触し、入力受理状況を記録 | 初回に1ハート減少、0.3秒入力不能、その後入力回復。0.8秒まで追加減少なし |
| AC-6 | 敵・壁に干渉しない直線でダッシュ。`d+0.10秒`付近に攻撃を一度入力。クールダウン内と終了後の再入力を別試行で確認 | 4タイル・論理時間0.25秒。攻撃はダッシュ終了時に一度発動。既存起点から0.6秒の再使用制限を維持 |

AC-6 は既存クールダウン起点を資料で確認し、その起点から0.50秒付近と0.70秒付近の入力を照合する。起点が資料化されていなければ未確認として返す。開始起点か終了起点かを新たに決めない。

### 追加回帰

全4環境で Grub 接触と Spitter 弾命中をそれぞれ確認する。

1. AC-3 の条件でダッシュ中の命中を防いだ後、両方の保護が終了したt=1.10付近の命中では通常の1ハート減少が成立する。
2. AC-4 の条件でダッシュ終了後の命中を防いだ後、両方の保護が終了したt=0.95付近の命中では通常の1ハート減少が成立する。
3. 保護中に異なるフレームで少なくとも2回の命中が成立しても、元の保護終了後の命中で通常被害が成立する。防いだ命中による保護延長がない。
4. 先行被弾なしでダッシュ中に複数の命中を防ぎ、終了後の`d+0.40秒`付近の命中では通常被害が成立する。

防いだ命中で新たな入力不能が始まらないことも確認する。条件を成立させるために敵の発射頻度、AI、攻撃仕様を変更しない。

### 証拠の有効性

各条件について、ビルド、FPS、入力方式、命中源、初期状態、配置、操作、実際のイベント時刻、ハート前後値を識別できることを確認する。接触や弾が通過しただけの試行を保護成功に数えず、命中成立の記録を必要とする。

- AC-3 は「被弾後0.8秒の終了点 < 命中 < ダッシュ終了」の実際の順序を確認する。
- AC-4 は「ダッシュ終了 < 命中 < 被弾後0.8秒の終了点」の実際の順序を確認する。
- フレーム番号、delta time、同一フレーム内のイベント順序を用い、目標時刻と実際の時刻を区別する。
- 30 FPSで0.25秒が整数フレームに一致しない点は論理時間と観察フレームを区別する。独自の許容誤差を新設しない。
- 同時境界、命中不成立、予定外の干渉、必要な順序や命中回数を満たさない試行は、当該条件の有効な証拠から除外する。
- 全条件の有効数、無効数、被害発生数と不足セルを明示する。
