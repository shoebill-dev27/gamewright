# D-010: G-001 は模擬ビルド 0.6 に基づいて「達成」と判定する。部屋 1・3 の据え置きは許容し、張り付き戦法・欠陥 D・出現待ちの伝わりは新しい課題に回す

## Decision

1. **判定**: G-001(戦闘の単調さの改善)は、**模擬ビルド 0.6 に基づく範囲で `goal-met`**。実機で確かめた判定ではない(D-008)。確信度は中程度。
2. **問題 A(部屋 1・3 に変化が少ない)**: D-002、D-003 の範囲内で許容する設計の帰結とする。突進を部屋 2・4・5 に限ったのは D-003 の決定どおり。部屋 1 は基本を覚える部屋、部屋 3 は Spitter により止まると撃たれる部屋として、それぞれ役割がある。今回は突進の追加や構成の変更をしない。
3. **問題 B(張り付き・離れすぎで突進を見ずに済む)**: この Goal の達成を妨げる理由にはしない。ただし新しい単調さを生む恐れがあるため、次の課題として挙げる。実機または Play で張り付き戦法が成立するか確認する。確認前に開始条件の数値(3.0〜6.0 タイル)は変えない。
4. **問題 F(部屋 5 の突進順序)**: 現時点では課題にとどめる。順序が読めないことが運任せの難しさになるかは、実機で確認する。
5. **欠陥 D(問題 E)**: 未再現の既知の疑いとして、次の課題の最優先に置く。規則はここで決めない。再現(`qa`)には Owner の元の報告文が要る。
6. **スコープ**: Goal の範囲を広げない。上記の次の課題は、すべて新しい Goal の提案とする。

## Rationale

- 成功条件は、戦闘中に位置取り・タイミング・敵の挙動への対応を実感できること。模擬ビルドの記述では、部屋 2・4・5 で、隅で立ち止まって振るだけの戦い方が通用しない。レーンを見て横に出るか、ダッシュで抜けるかを選ぶ場面が生まれる。部屋 3 は元から Spitter が止まる戦い方を許さない。回復の隙(0.8 秒)が反撃の機会として読める。Playtester も「見てから避ける場面が自然に生まれる」と報告している。
- D-002 の想定は「部屋の構成と進行を主軸にし、突進を 1 つだけ併用する」で、変化が全部屋に均等に出るとは言っていない。5 部屋のうち 3 部屋で型が変わり、進行(1 → 2 → 3 → 4 → 5)も付いたので、方向の狙いには合う。
- 欠陥 D は、このビルド以前から既にある挙動で、模擬ビルドの記述では「ときどき」起きるとされている。達成を覆すと判断するには証拠が足りない。ただし、突進を避けるダッシュの信頼を損ねうるので、先送りにせず優先して扱う。
- Verify(`qa`、`art-director`)に fail はなく、見た目の混同などの報告も出ていない。

## Limits(この判定が言えないこと)

- 判定の証拠は、模擬ビルドの記述と、それを読んで思い描いた体験の報告である。実時間の感触、画面での見え方、ゲームパッドの操作感、音、30/60 FPS の差は確認されていない。
- 「飽きにくくなったか」は、実機で遊んで初めて言える。この判定はその代わりにならない。

## Alternatives considered

- **`goal-not-met` にして Diagnose に戻す**: 問題 A・B・F は、いずれも成功条件を満たさないほどの証拠にはなっていない(A は設計の範囲内、B・F は未検証)。戻しても、新しい診断の材料が模擬ビルドの記述では得られない。採らない。
- **部屋 1・3 にも突進を足してから達成とする**: D-003 の変更とスコープの拡大にあたる。採らない。
- **欠陥 D を先に再現してから判定する**: 原文が入力になく、模擬ビルドの判定を止める理由にならない。採らない。

## Revisit when

- 実機または実プレイで、張り付き戦法が突進を無意味にして新しい単調さになると分かった場合(D-003 の「歩きだけで避けられダッシュの理由が出ない」にも関わる)。
- 欠陥 D の再現結果により、被弾直後のダッシュが突進の回避を成立させないと分かった場合。
- 実機の確認(H1〜H4)で、0.7 秒の予告が足りない、または単調さの主因が別にあると分かった場合(D-002 の Revisit when に該当)。
- 実際のコードベースが用意された場合(D-008)。
