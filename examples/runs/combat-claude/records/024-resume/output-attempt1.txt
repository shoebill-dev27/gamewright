# D-008: 模擬専用のサンプルとして進める — `sim/repo-notes.md` をコードとして扱い、Build は変更内容を Handoff に正確に書いた時点で完了、Goal の判定は(模擬と明記した)模擬ビルドに基づく

## Decision

Owner は Escalation 20 の選択肢 C を選んだ。Owner の言葉(原文):

> Cで進めてください。このプロジェクトは模擬専用のサンプルなので、sim/repo-notes.md をコードとして扱い、Build は変更内容を Handoff に正確に書いた時点で完了とします。模擬ビルドは私ではなくランタイムのシミュレーターが、その変更内容から作ります。結果には模擬であることを明記したうえで、Goal の判定は模擬ビルドに基づいて行ってください。

これにより、次を定める。

1. **コードの扱い。** `sim/repo-notes.md` を、このプロジェクトのコードとして扱う。D-007 の台帳 7 項目は、`sim/repo-notes.md` の記述を確認の根拠にしてよい。`sim/repo-notes.md` に書かれていない項目は「記述なし」と明記し、変更内容の中で前提として宣言する(確認済みとは書かない)。
2. **Build の完了条件。** Build(`gameplay-engineer`)は、ゲームへの変更内容を Handoff に正確に書いた時点で完了とする。実際のビルド・テスト実行は求めない。テストは「追加するテストの内容」として書き、実行済みとは書かない。D-007 の 7(コードがなければ再試行せず返す)は、`sim/repo-notes.md` がコードの代わりになるため、この Build には適用しない。
3. **模擬ビルドの作成者。** 模擬ビルドは Owner ではなく、ランタイムのシミュレーターが Build の変更内容から作る。したがって変更内容は、シミュレーターがそれだけでビルドの挙動を再現できる精度で書かなければならない。
4. **Verify・Play・Review。** 模擬ビルド(`sim/build-*.md`)に対して行う。すべての結果に「模擬ビルドに基づく」と明記する。
5. **Goal の判定。** Owner の指示により、Goal の達成判定は模擬ビルドに基づいて行ってよい。ただし判定には「模擬ビルドに基づく」と明記する。ゲームパッドの実機の操作感、実時間での 0.7 秒の予告の十分さ、暗い床での読み取りやすさ(H1〜H4)は模擬では確かめられないため、「未確認」と明記して残す。

限界: D-001〜D-007、ビジョンの柱、ラン長、入力ボタンは変えない。実在のリポジトリを使う Option A は選ばれていない。

## Rationale

Owner が、このプロジェクトは模擬専用のサンプルであり、模擬ビルドが成果物の形だと明示した。この前提では、コードがないことは入力の欠落ではなく、プロジェクトの形である。D-007 の 7 が避けようとした「未確認の前提を確認済みとして扱うこと」は、「模擬である」という明記と、記述なしの項目の宣言で防ぐ。

## Alternatives considered

- **A: 実際のリポジトリとビルド・テスト手段の提供。** Owner は選ばなかった(サンプルのため実コードがない)。
- **B: 計画と受け入れ基準の確定までに縮小。** Studio の推奨だったが、Owner は Goal の判定まで進めることを選んだ。

## Revisit when

実在のリポジトリが用意されたとき(Option A に移り、実機で検証し直す)。模擬ビルドで判定した結果と実機の確認が食い違ったとき。`sim/repo-notes.md` に、変更内容の前提と矛盾する記述が見つかったとき。

# G-001: 戦闘の単調さの改善

## Owner request

> 戦闘が単調なので改善したい

## Interpretation

体験上の Goal。ビルド 0.3 の戦闘が、想定プレイヤー(短時間で濃いランを求め、回避と間合いに慣れたアクション好き)にとって単調に感じられない状態にする。
成功条件は質的なもので、プレイヤーが戦闘中に、ほぼ同じ行動の繰り返しではなく、状況に応じた位置取り・タイミング・敵の挙動への対応といった判断を実感できること。数値基準は Design の受け入れ基準で、最終判定は Review で決める。

Owner の決定(D-008)により、このプロジェクトは模擬専用のサンプルとして扱う。Goal の判定は、変更内容からシミュレーターが作る模擬ビルドに基づいて行い、すべての結果に「模擬ビルドに基づく」と明記する。実機でしか確かめられない点(H1〜H4)は未確認として残す。

範囲外:
- 新しい入力ボタンの追加(D-001 により Owner 承認なしでは不可)。
- 戦闘以外のシステムの変更。
- ラン長(15–20分)やビジョンの柱の変更。
- 原因の特定前に解決策を決めること。
