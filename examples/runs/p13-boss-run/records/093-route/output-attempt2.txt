# 77: studio → technical-director — E1連続partial3回を受けた既存作業の再分割

## Task

既存E1を、実接続・互換診断・実経路監査・証拠出力の依存と完了条件が明確な単位へ再計画する。実装は行わず、供給上限内で完結できる次のEngineer作業と後続への引渡し条件を定める。

## Context

72・74・76が同じE1の連続partial3回となったため、ループ制限により再計画へ戻す。70は別作業E0であり数えない。60のfailを維持し、E2以降と独立QAはまだ開かない。

Goalは79/40 operationsで予算超過。これは既存Build作業の再分割であり、新しい検証目的や工程を追加する依頼ではない。予算は変更しない。

## Findings

76で保存された変更はtest_split_c.pyの生成入力再生診断と、test_g002_evidence.pyのhelper自己試験本文の再表示。runtimeはsource e99408d647c7で160 tests OKを報告した。必要な診断行の完全な収録は未確認であり、成功件数で補わない。

実dodgerは旧経路を使い、active chargeのphase_leftを読む。prototypeの限定監査成功は実経路の公開情報限定を証明しない。未保存接続案は不採用で、被弾差の原因は未確定。

76が提示した分割候補は次のとおり。

1. 直接呼出・_Proxy・play_room・play_runの実接続と、warning記憶の所有・寿命・入場/retry初期化。
2. 接続後の生成／公開再生の全フレーム対照と、必要な制御前後・被弾接触条件の診断。
3. 接続済み全経路の許可外参照禁止、不変性、記憶、全分岐のassert。
4. 判断番号・grid・公開入力・記憶由来・候補／除外・選択・実発行ボタンと、状態／判断の出力整備。

接続が後続診断・監査・証拠の前提となる。計画責任者としてこの依存を検証し、既存assertを維持した完了単位を定める。詳細な未完了項目、全13試験ファイルのQA配布台帳、新規1IDと既存追加5IDの割当は76を参照する。
