# 77: studio → game-director — 予算超過下の残工程と継続範囲を判断する

## Task

既存予定工程7dを前倒しし、Owner request「最後に手応えのあるボス戦がほしい」に必要な残作業と、省略可能な予定作業を判断する。79/40 operationsの超過とE1連続partial3回を踏まえ、既存承認内で成立する経路を示すか、継続費用についてOwner向けEscalationを作る。

## Context

今回のRouteは新しいstageを追加していない。76を受領して75を完了記録し、既存のplanned Decideを開いた。Studioにはゲームの必要範囲を決める権限がないため、残工程を独断でskippedにしていない。

D-023は利用可能な供給内での継続指示であり、予算変更や未確認基準の免除ではない。GoalのOwner requestとInterpretationは維持する。

## Findings

- 72・74・76は同じE1の連続partial3回。70はE0であり含めない。
- 76の保存済みsource e99408d647c7はruntimeで160 tests OK。診断試験と出力helperを変更したが、製品・botの行動変更はない。
- 実dodgerは旧経路のまま。公開境界接続、被弾差の根因、記憶初期化、全分岐監査、判断本文は未成立。必要診断本文の切断・未表示を成功件数で補えない。
- ループ制限により、同じE1を第四の直接Buildへ戻せない。継続にはTechnical Directorによる分割・再計画が必要。ただし、このRouteではそのStepを追加・開設していない。
- 68の残計画はE2接触診断、E3四条件再測定、E4保持回帰・記録比較、E5公開再生、独立Q1〜Q6。その後に既存予定の限定Art Verify、独立Play、Designer実測後判断、Reviewがある。
- 60のfailは維持する。歴史的確認不能はD-024により現行検証・記録比較と分離し、最終判断へ残す。

## Decisions already made

- D-015〜D-019：連続ラン・最終ボスの範囲、体験方向、仕様・評価契約。
- D-021：テキスト表示とスクリプト実行、Studio内の独立QA・Playで進める。
- D-022：表示・弾・長時間観測の補足契約。
- D-023：個別Load、@need一度最大8件、@run最大3回、各出力最大2万字。全文保存先と変更前ビルドはない。
- D-024：歴史的確認不能をpass・免除へ読み替えない。

## Constraints

予算40はOwnerだけがResumeで変更できる。予算超過中にstageを増やす計画を承認済みとして扱わない。

方向・範囲の判断を行い、技術的な分割方法はTechnical Directorに委ねる。必要な継続が費用・範囲の大幅変更となる場合はOwnerへ戻す。Owner requestの再解釈、仕様・難度・秒数ゲートの変更を暗黙に行わない。

Build後のVerifyとQA・Playの独立性を守る。未確認を合格とせず、既存assertを弱めない。存在しない供給を再要求しない。

## Open questions

1. 既存の残工程のうち、今回のOwner requestに不可欠なもの、省略可能なものはどれか。省略は工程・対象ごとに理由を示せるか。
2. E1の技術再計画が必要な状況で、既存承認内の継続経路は成立するか。成立しない場合、どの継続費用をOwnerに判断してもらうべきか。
3. 歴史的確認不能を保持した後続評価の条件を現時点で定められるか。現行検証の未完了とは分けて示すこと。

## Expected output

既存承認内で進められる場合は、必要な予定工程・省略する予定工程・各理由・次の担当を明示したHandoffをstudioへ返す。E1継続を必要とするなら、直接Buildではなく技術再計画が必要な点と、予算制約への適合を明示する。

費用・範囲の大幅変更やGoal再解釈が必要なら、prepare-owner-escalationに従い、日本語で選択肢・推奨・各選択後の経路を持つOwner向けEscalationを作る。既存の供給質問を繰り返さない。判断だけでGoal達成やQA合格を宣言しない。
