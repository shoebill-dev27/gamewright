# 27: Owner decision needed — 「被弾硬直中のボタン入力」がビルド記述に反映されていない

## Question

検証用ビルド記述 `sim/build-0.4.md` に、被弾硬直中のダッシュ/攻撃入力が「無視される」ことを反映（または別の形で確認）してよいか、それとも検証範囲を絞って先へ進めるか。

## Why this needs the Owner

作業は、どの Role も作れない情報で止まっている。検証の対象である検証用ビルドの記述（`sim/build-0.4.md`）に、ハンドオフ 20 で行ったはずの変更（被弾硬直中の入力を破棄し、バッファせず、硬直終了時にも発動しない）が載っていない。ドライラン用プロジェクトでは `sim/` はランタイムのシミュレータが更新するもので、Studio や各 Role は書けない。

QA は同じ欠落で 3 回、結論なしの `question` を返した（ハンドオフ 15、21、26）。ハンドオフ 26 は、ハンドオフ 20 の変更後に最新のファイルを読んだうえで、旧記述の「0.3 と同じ挙動」のままだったと報告している。目標記録に書いた規則どおり、ハンドオフ 23 以降に同じ観測で `question` が返ったためエスカレーションする。これ以上 Role に回しても同じ結果になる。また、検証範囲を狭めることは検証の基準を変える判断で、Studio が決めるべきではない。

## Options

### Option A — ビルド記述を更新して QA に再検証させる

オーナー（またはシミュレータを動かす担当）が `sim/build-0.4.md` に、次の 6 点を観測可能な挙動として反映する。見出し「0.3.1」とファイル名 0.4 の不一致も直せるなら直す。
1. 硬直 0.3 秒中のダッシュ入力ではダッシュが始まらず、クールダウンも始まらない。
2. 硬直中の攻撃入力では振りが出ず、「ダッシュ中の攻撃予約」にも入らない。
3. どちらの入力も、硬直終了時（0.3 秒）に発動も保存もされない。
4. 硬直終了まで押しっぱなしにしても発動せず、離して押し直せば通常どおり動く。
5. 0.3 秒以降の入力は通常どおり受け付ける（境界 1 フレームは 30/60 FPS で差が出うる）。
6. 硬直の長さは 30/60 FPS で同じ。

コストは小さい。リスクはほぼない。可逆。
If chosen: QA に再検証を依頼する。このときのハンドオフは、旧記述が見えないよう Studio が新規に作る。合格なら Phase 1 Build（ステップ 6）を開く。不合格なら gameplay-engineer に戻す。

### Option B — ハンドオフ 20 の記述をビルド記録として扱い、QA に再検証させる

`sim/` は更新せず、gameplay-engineer のハンドオフ 20 にある変更内容を、そのまま「ビルドの記述」として QA に渡す。QA は自分で観測するのではなく、技術的な記述を元に判定することになる。
リスク: QA の独立性が下がる。QA の役割は実装者の説明ではなくビルドから検証することだが、ここでは実装者の説明が証拠になる。記述が実際の挙動とずれていても気づけない。
If chosen: Studio がハンドオフ 20 から送信者の自己評価を除いた事実部分だけを QA 用に作り、「ビルドの代用記録」と明記して渡す。QA の結論には「実装者の記述に基づく」と残す。

### Option C — 被弾硬直中の入力は今は検証せず、Phase 1 に進む

基準 1、3、4、6（問題なし）で当面の合否とし、基準 2 と 5 の「硬直中の入力」部分は後で、ビルドが更新されたときに検証する。
リスク: D-003 の挙動が未検証のまま Phase 1 の上に積まれる。後で不合格になれば手戻りが大きくなる。
If chosen: Studio が QA に基準 2/5 の該当部分を「未検証・持ち越し」とした限定合格を求め、Phase 1 Build（ステップ 6）を開く。持ち越し項目は Phase 1 の検証（ステップ 7）に加える。

## Studio recommendation

Option A。

## Reasoning

欠けているのは仕様でも実装の判断でもなく、ビルドの記述が古いままという一点だけで、直せば QA は数分で結論を出せる。独立した検証という QA の前提も保てる。Option B はそれが無理な場合の次善策で、Option C は D-003 の確認を先送りするのでおすすめしない。もし `sim/` を更新する手段が本当にない場合は、Option B を推奨する。

## Meanwhile

Nothing; all remaining steps depend on this answer. Phase 1 Build（ステップ 6）は、4a′ の結論が出るまで開かない。Phase 2 のステップは Phase 1 の後ろで tentative のまま。
