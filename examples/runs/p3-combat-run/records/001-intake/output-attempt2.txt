# G-001: 戦闘の単調さの改善

## Owner request

> 戦闘が単調なので改善したい

## Interpretation

Success condition (qualitative): a player on the project's player profile (action players who like dodging and spacing) plays the combat in the prototype and no longer experiences it as monotonous. Combat feels varied through positioning, timing and enemy behavior, and stays within the vision. Numeric thresholds belong to Design (acceptance criteria) and the final verdict to Review.

Out of scope:
- New input buttons (D-001: attack, dash and pause only, without Owner approval).
- Changes to run length and to non-combat systems.
- New biomes or large content expansion.

Constraints that apply: the one-button combat pillar (D-001), readable threats, correct play at 30 and 60 FPS, and reuse of existing systems where possible.

Escalation check: the Goal does not need reinterpretation and does not conflict with the vision or D-001, as long as the improvement stays within one-button combat. No immediate escalation. If the diagnosis shows that fixing the monotony would require breaking D-001 (a new button), that is an escalation trigger.

## Unknowns

Entry questions the Project Context cannot answer:
- Observe: Has the monotony been observed first-hand? What exactly feels monotonous (which fights, which enemies, which moments)? The Project Context only has the Owner's one-line impression. This is an experience problem (works as specified, feels wrong), so the playtester observes.
- Diagnose: The cause is unknown (enemy behavior, lack of player options, room design, pacing, feedback, and so on).
- Decide: Likely a real choice of direction once causes and options are known. Tentative.
- Design: The intended changed behavior is not specified. It will be, once a direction is chosen.
- Plan: Unknown until the design exists. Tentative (needed if the change is cross-system, risky or parallelizable).
- Build: The game must change. Planned.
- Verify: Always after Build.
- Play: The Goal is about how the game feels.
- Review: This is an experience Goal.

Skipped: none. Nothing in the Project Context answers any of these questions yet. `design/combat.md` exists, and the first Role that needs it will read it.
