# D-005: The Owner places the `manual.md` draft by hand (Option A)

## Decision

The Owner saved the "Draft `manual.md`" from `18-gameplay-engineer-to-studio.md` unchanged as `manual.md` in the project root. The gameplay-engineer does not write `manual.md`. The next Build step only checks that the placed file satisfies `ManualTest` (`run_tests`, expected 34/34). If it passes, Verify opens.

Owner's words (Escalation 21): 「A。18 の Draft manual.md を変更せずにプロジェクト直下の manual.md として置きました（Owner の代理として Studio の推奨案を採用）。」

Conditions: the draft is placed unchanged. If `run_tests` shows the draft is wrong, the fix goes back to the Owner or to a Role the Owner authorizes. The gameplay-engineer's write list does not include `manual.md`.

Limits: this covers only how `manual.md` for build 0.5 got into place. It does not change D-004 item 5 (the gameplay-engineer owns the manual in principle) and grants no standing write access.

## Rationale

The draft was checked against the implementation by reading, so placing it is low risk and reversible. It removes the block with one manual action and needs no change to the execution environment. `run_tests` then confirms what was only read before.

## Alternatives considered

- **B, write access for the gameplay-engineer:** the roles fit, but it needs an environment change. The outcome would be the same as A.
- **C, skip `manual.md` and go to Verify:** AC-15, V-5 and `ManualTest` would stay unverified and the problem would return before Review. Not chosen.

## Revisit when

`ManualTest` fails on the placed file, or a later change to controls or the script format makes `manual.md` need edits again. Then ask for write access (B) rather than another manual placement.
