## Findings

From the QA report (76), section 1 and defect 1:

- Failing test: `test_wind_up_and_hit_messages_name_the_variant` (`VariantMessageTest`, `repo/tests/test_game.py`, around line 763).
- Failure: `AssertionError: 3 != 1 : (30, 'grub')` on `out.count("a grub rears back")`.
- Cause (QA): the test runs 3 s with a still player and expects one wind-up message. A still player is hit, the enemy recovers, walks up and winds up again, so more than one wind-up message is correct behavior. QA's direct trace showed the runner rearing back at 0.033 s and again at 1.167 s at 30 FPS. For the grub at 30 FPS QA derived wind-ups at about 0.03, 1.5 and 2.8 s, which gives the 3 the test counted (derived, not separately traced).
- The assertion stops at the first failure, so the runner and brute cases and the 60 FPS cases of this test never ran. They may fail for the same reason once the first assertion is fixed.
- Expected source: design/combat-step68.md V-a says "each wind-up prints its message once". It does not say "once in 3 s".

Acceptance criteria for the fix:

1. The whole suite is green via `run_tests`.
2. The test still checks, for every variant (grub, runner, brute) at both 30 and 60 FPS: exactly one wind-up message per wind-up (for example, a window that contains one wind-up, or a count tied to the number of wind-ups), and a hit message naming the matching variant. It must not be weakened to "at least one".
3. No change to `repo/game.py` behavior, to `repo/bots.py`, or to other tests' meaning. If you think the fix needs a production change, stop and hand back with the reason.
